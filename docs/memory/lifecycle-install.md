# Domain: lifecycle-install

Summary: ~/.cairn/install 레이아웃·legacy 이전·호스트 선택·runtime 유예, lifecycle 트랜잭션, 자동 업그레이드, CLI exit 규약. 설치·CLI를 바꿀 때 읽는다.

## Scope

`scripts/cairn-lifecycle*.mjs`(경로 상수 `-layout`, 호스트 선택 `-hosts`), `scripts/cairn-paths.mjs`(runtime locator, `cairnHome`·`installRoot`), 자동 업그레이드 `scripts/cairn-auto-upgrade.mjs`·`scripts/cairn-update-state.mjs`, `scripts/cairn.mjs`의 명령 분기, `scripts/cairn-cleanup.mjs`의 CLI. goal 상태 정리 규칙은 `goal-state.md`, SessionStart 알림 문구·예산은 `hook-context.md`, 릴리스 절차는 `release-process.md`. 설계·결정 기록은 `docs/plan/auto-upgrade-cairn-home.md`.

## Facts

### 설치 경로와 소유권

- 루트는 `CAIRN_HOME ?? ~/.cairn`이고 lifecycle 관리 파일은 모두 `<cairnHome>/install/` 아래다: manifest `lifecycle.json`(schema 2), `lifecycle.lock`(기본 대기 60초, `CAIRN_LIFECYCLE_LOCK_TIMEOUT_MS`), journal `transaction.json`·`transactions/`, canonical runtime `runtime/<version>/`, Codex marketplace source `codex/`(`.agents/plugins/marketplace.json`, `plugins/cairn/`), Claude marketplace `claude/`. 같은 루트의 `projects/`(goal 상태), `config.json`(사용자 설정), `update/`(자동 업그레이드 상태)는 관리 대상이 아니다. 출처: `scripts/cairn-paths.mjs:9-22`, `scripts/cairn-lifecycle-layout.mjs:11-35,53-66`, `scripts/cairn-lifecycle-lock.mjs:6`, `test/lifecycle-transaction.test.mjs` "install places the manifest, canonical runtime, Codex marketplace source, and Claude marketplace under CAIRN_HOME/install".
- Codex 호스트 캐시 `$CODEX_HOME/plugins/cache/cairn/cairn/<version>/`(id `codex-runtime`)는 Codex를 선택했을 때만 만든다. Codex는 자기 캐시에 이 디렉터리가 있어야 `cairn@cairn`을 설치된 것으로 본다. 출처: `scripts/cairn-lifecycle-layout.mjs:7-17`, `scripts/cairn-lifecycle-staging.mjs:25,42-57`, `test/lifecycle-transaction.test.mjs` "Codex A/B gate proves the versioned custom cache is required".
- 모든 runtime locator와 Claude hook은 canonical runtime을 가리킨다. 패키지 소스 manifest에는 `hooks` 필드가 없고 설치된 사본에만 붙는다. 출처: `scripts/cairn-lifecycle-staging.mjs:21-24,122-130`, `test/lifecycle-transaction.test.mjs` "every runtime locator and Claude hook points at the canonical runtime".
- 호스트별 표면:
  - Claude Code: `~/.claude/commands`, `~/.claude/agents`, runtime locator `~/.claude/cairn/runtime.json`, 얇은 Claude plugin(`install/claude/`).
  - Antigravity: `~/.gemini/config`, `~/.gemini/antigravity-cli`. 예전 `~/.agents`에서는 이전한다.
  - 각 경로는 `CLAUDE_HOME`, `ANTIGRAVITY_HOME`, `ANTIGRAVITY_CLI_HOME`, `CODEX_HOME`, `CODEX_CONFIG_PATH`로 바꾸며 `CAIRN_HOME`과 독립이다. 테스트는 모두 이 env로 격리한다.
- 트랜잭션 단계는 `core → codex → claude → antigravity → config → cleanup`이다. 실패하면 이전 runtime과 manifest를 복구하고, 중단된 journal은 다음 lifecycle 실행이 복구한다. journal 항목은 허용 목록(id·phase·경로)으로 검사한다. 출처: `scripts/cairn-lifecycle.mjs:53`, `scripts/cairn-lifecycle-transaction-journal.mjs:12-21,124,152`, `test/lifecycle-transaction.test.mjs` "upgrade failure restores the previous runtime and manifest", "the next lifecycle run recovers a crash journal from durable backup".
- journal 검사는 실행 중인 CLI 버전과 무관하다. `runtime`·`codex-runtime`(legacy 스택의 `codex-runtime` 포함)·`previous-codex-runtime` 항목은 자기 parent의 유효한 `<version>` 직계 자식이면 허용하고, parent 밖·잘못된 버전 형식·다른 phase·type은 거부한다. 그래서 설치본과 버전이 다른 CLI의 rollback과 중단 복구(0.6.0이 남긴 legacy journal 포함)가 동작한다. 출처: `scripts/cairn-lifecycle-transaction-journal.mjs` `versionedRuntimeTarget`·`previousRuntimeTarget`, `test/lifecycle-transaction.test.mjs` "a newer CLI's failed uninstall of a 0.6.0 installation rolls back and restores the Claude registration", "a newer CLI recovers a 0.6.0 journal interrupted after the codex phase and completes the migration", "an older CLI's failed uninstall of a newer installation rolls back", "a newer CLI's migration failure after cleanup restores the 0.6.0 installation", "journal schema rejects entries outside the current allowlist". 이 테스트들은 작업 트리를 복사해 버전만 올린 CLI(`newerCli`)로 실행한다.
- 관리 대상 파일·트리가 설치 digest와 다르면 upgrade·uninstall이 거부하고 보존한다(`Managed artifact was modified`, `Refusing to uninstall modified managed artifacts`). manifest 형태(`hosts`·`origin`·`retained`·schema 포함)가 잘못되거나 허용 목록 밖을 가리켜도 fail-closed다. 출처: `scripts/cairn-lifecycle-integrity.mjs:49-80`, `scripts/cairn-lifecycle-commands.mjs:276`, `test/lifecycle-transaction.test.mjs` "schema 2 ownership fields fail closed when hosts, origin, retained, or the schema version are invalid".
- 예외: 공유 `config.toml`은 mutable merge surface다. Cairn 소유 section(`[marketplaces.cairn]`, `[plugins."cairn@cairn"]`, `cairn@cairn:` hook trust)만 재조정·제거한다. section 뒤의 빈 줄·주석(boundary trivia)과 사용자 section은 보존한다. symlink config는 거부한다. `marketplaces.cairn`은 `install/codex/`를 `source_type = "local"`로 가리킨다. 출처: `scripts/cairn-lifecycle-config.mjs:6-40`, `scripts/cairn-lifecycle-transaction-targets.mjs:9-59`, `test/lifecycle-transaction.test.mjs` "config projection points marketplaces.cairn at the Codex marketplace root and keeps hook trust hashes".
- 정확히 일치하는 0.2.2 legacy 트리만 adoption한다(`scripts/release-integrity-0.2.2.json` SHA-256 목록). 수정되거나 파일이 더 있으면 건드리지 않고 거부한다. 출처: `test/lifecycle-transaction.test.mjs` "an exact legacy 0.2.2 tree is adopted once and upgraded transactionally" 외 3개.
- 설치본(`install/` 아래이거나 `$CODEX_HOME/plugins/cache/cairn` 아래) 안의 CLI로 install·upgrade하면 `Run install or upgrade from the Cairn package/global source, not from the installed cache.`로 거부한다. 출처: `scripts/cairn-lifecycle-commands.mjs:46-48`, `test/installed-plugin.test.mjs:113-116`.
- 설치본(현재 manifest, 없으면 legacy manifest)의 `version`이 CLI 버전보다 높으면(`compareVersions`, prerelease는 같은 릴리스와 같다) install·upgrade는 lock 안에서 journal을 복구한 뒤 transaction 전에 `Installed Cairn <installed> is newer than this CLI <cli>; run the newer CLI, or pass --allow-downgrade to install <cli>`로 거부하고 아무것도 바꾸지 않는다. `--allow-downgrade`(install·upgrade만, `--auto`와 함께 쓰면 거부)를 주면 내려간다. uninstall은 버전과 무관하다. 출처: `scripts/cairn-lifecycle-commands.mjs` `recordedVersion`, `test/lifecycle-transaction.test.mjs` "an older CLI refuses to replace a newer installation unless --allow-downgrade is given", "a legacy manifest newer than the CLI is refused without changes".
- doctor는 manifest 버전이 CLI 버전과 다르면 `Hosts:` 다음 줄에 `CLI version <cli> differs from installed version <installed>`를 출력한다. 버전에 의존하는 경로(canonical runtime, Codex 캐시 runtime, runtime locator)와 버전 비교(`Claude plugin files`, `Claude plugin cache version`, `Codex plugin version`)는 manifest 버전 기준이다(manifest가 없거나 버전이 잘못되면 CLI 버전). 출처: `scripts/cairn-lifecycle-commands.mjs` `doctor`, `test/lifecycle-transaction.test.mjs` "doctor from a CLI of another version checks the installed version and reports the difference".
- symlink 조상 검사는 `CAIRN_HOME` 기준 lifecycle 경로와 선택된 호스트의 경로만 본다. 출처: `scripts/cairn-lifecycle.mjs:175-204`, `test/lifecycle-hardening.test.mjs` "install rejects a symlinked CAIRN_HOME install ancestor without outside writes".
- 빈 managed root만 지운다. `install/`과 Codex 캐시 루트는 비었을 때만 lock 해제 뒤 제거하고, `CAIRN_HOME` 자체는 남긴다. 출처: `scripts/cairn-lifecycle.mjs:230-234`, `test/lifecycle-transaction.test.mjs` "managed-only uninstall prunes the install root and Codex cache scaffolds and can reinstall".

### legacy(0.6.0 이하) 이전

- 0.6.0 이하 레이아웃(모든 것이 `$CODEX_HOME/plugins/cache/cairn`, manifest `.cairn/lifecycle.json` schema 1)은 `createLayout`의 `legacy` 경로 세트와 별도 legacy 스택이 읽는다. legacy 스택은 설치하지 않는다. 출처: `scripts/cairn-lifecycle-layout.mjs:37-49`, `scripts/cairn-lifecycle.mjs:67-83`.
- `cairn install`/`upgrade` 한 번이 같은 트랜잭션 안에서 legacy 설치를 `install/`로 옮기고 legacy manifest와 옛 위치(`legacy-root-*` id)를 지운다. Claude marketplace는 옛 등록을 지우고 새 경로로 다시 등록한다. 출처: `scripts/cairn-lifecycle-commands.mjs:76-96,129-131,418-427`, `scripts/cairn-lifecycle-claude.mjs:133-143`, `test/lifecycle-transaction.test.mjs` "a published 0.6.0 installation migrates to CAIRN_HOME with one upgrade".
- lock은 새 lock을 먼저, legacy 상태 루트가 있으면 legacy lock을 이어서 잡는다(0.6.0 프로세스와 직렬화). legacy journal을 먼저 복구한다. 출처: `scripts/cairn-lifecycle.mjs:165-173`, `scripts/cairn-lifecycle-commands.mjs:394-399`, `test/lifecycle-transaction.test.mjs` "migration recovers an interrupted legacy journal first", "a live legacy lifecycle lock blocks migration".
- 수정된 legacy 관리 파일이 있으면 아무것도 바꾸지 않고 거부한다. 이전 중 실패·중단은 복구된다. legacy와 현재 manifest가 함께 있으면 fail-closed다. 출처: `test/lifecycle-transaction.test.mjs` "migration refuses a modified legacy managed artifact and changes nothing", "the next lifecycle run recovers a migration that crashed after the cleanup phase", "legacy and current manifests together fail closed".
- legacy 설치는 모든 호스트로 이전한다. 전체가 아닌 `--hosts`와 함께 주면 `… (a legacy installation migrates with every host; run cairn upgrade first, then choose hosts)`로 거부한다. 이전에는 runtime 유예가 적용되지 않는다(옛 Codex 캐시 사본을 `previous-codex-runtime`으로 제거). 출처: `scripts/cairn-lifecycle-commands.mjs:90-95,422-425`.
- legacy 설치의 uninstall은 이전하지 않고 legacy 스택이 그 자리에서 제거한다. doctor는 현재 manifest가 없고 legacy manifest가 있으면 `Legacy installation found at <root>; run cairn upgrade to migrate`를 출력한다. 출처: `scripts/cairn-lifecycle-commands.mjs:263-267,383-385`, `test/lifecycle-transaction.test.mjs` "uninstall removes a legacy-layout installation without migrating", "doctor reports a legacy installation with a migration hint".
- 0.6.0 이하 CLI는 `install/` 레이아웃을 모른다. 이전된 설치에 옛 CLI로 install하면 legacy manifest가 새로 생겨 두 manifest 동시 존재로 다음 실행이 거부된다. 그래서 이전 뒤에는 새 버전 CLI로만 다룬다. 출처: `scripts/cairn-lifecycle-commands.mjs:401-405`.

### 호스트 선택

- 호스트 id는 `codex`, `claude`, `antigravity`(정규 순서)다. `--hosts <list>`/`--hosts=<list>`는 `install`·`upgrade`만 받고 값은 `all` 또는 쉼표 목록이다. 누락·빈 값·모르는 이름·중복·두 번 지정은 lock·stage 전에 거부한다. 출처: `scripts/cairn-lifecycle-hosts.mjs:4-27`, `scripts/cairn-lifecycle.mjs:110-134`, `test/lifecycle-hardening.test.mjs` "--hosts accepts all or a comma list and rejects missing, empty, unknown, and duplicate values before mutation".
- 대화형 prompt(전체 기본 / Claude Code만 / Codex만 / Antigravity만 / 쉼표 목록, en·ko)는 `install`에서 `--hosts`가 없고, 현재·legacy manifest가 모두 없고, stdin·stdout이 TTY이고, `CI`가 없을 때만 lock 밖에서 묻는다. 잘못된 입력이면 다시 물어 총 3회 시도하고, 그래도 유효하지 않거나 EOF면 exit 1. 그 밖에는 기록된 선택, 없으면 전체다. 출처: `scripts/cairn-lifecycle-hosts.mjs:64-98`, `scripts/cairn-lifecycle.mjs:88-90,136-143`, `test/lifecycle.test.mjs` "no prompt for upgrade, for an existing manifest, for --hosts, without a TTY, or when CI is set", "a non-interactive install without --hosts installs every host".
- 선택은 manifest `hosts`에 기록되고 upgrade·doctor·uninstall이 따른다. 빠진 호스트의 대상은 자기 id로 제거되므로 수정돼 있으면 거부한다. Claude를 빼면 파일 제거 전에 등록을 해제하고 rollback 시 다시 등록한다. 출처: `scripts/cairn-lifecycle-commands.mjs:64-65,98-103,158-177`, `test/lifecycle.test.mjs` "upgrade --hosts adds a host and removes a deselected host", "deselecting a host with a modified artifact is refused and changes nothing", "a rollback after Claude deselection re-registers the plugin".
- doctor 첫 줄은 `Hosts: <id 쉼표 목록>`이고 선택된 호스트만 검사하며 그 호스트 CLI만 실행한다. 출처: `scripts/cairn-lifecycle-commands.mjs:318-324`, `test/lifecycle.test.mjs` "doctor checks only the selected hosts and prints the selection".

### runtime 유예

- 버전이 바뀌는 install/upgrade는 직전 canonical runtime(`runtime`)과 Codex 캐시 사본(`codex-runtime`)을 manifest `retained`에 기록하고 3일(`RETAINED_RUNTIME_GRACE_MS`), id별 최대 3개(`RETAINED_RUNTIME_LIMIT`) 남긴다. 기간이 지나거나 상한을 넘은 것은 다음 install/upgrade의 cleanup 단계가 `retired-<id>-<version>`으로 제거한다. uninstall은 모두 제거한다. 수정된 유예 runtime은 upgrade·uninstall을 막는다. 출처: `scripts/cairn-lifecycle-integrity.mjs:11-14`, `scripts/cairn-lifecycle-commands.mjs:183-231,271-298`, `test/lifecycle-transaction.test.mjs` "a retained runtime past the grace period is removed by the next upgrade", "retained runtimes are capped at three", "uninstall removes retained runtimes", "a modified retained runtime blocks upgrade and uninstall".
- 유예 runtime 경로가 외부(Codex, 사용자)에서 삭제됐으면 이미 제거된 것으로 본다. install·upgrade·uninstall은 그 항목을 `retained`에서 빼고 진행하고, doctor `ownership digests`도 실패로 보지 않는다. 존재하지만 digest가 다르면 지금처럼 fail-closed다. 출처: `scripts/cairn-lifecycle-integrity.mjs` `withoutMissingRetained`·`ownershipDigestsValid`, `test/lifecycle-transaction.test.mjs` "a retained runtime removed outside Cairn is dropped by doctor, upgrade, and uninstall".
- 릴리스와 같거나 높은 Codex 캐시 사본은 유예하지 않고 제거한다. Codex는 캐시에서 가장 높은 버전을 로드하기 때문이다(G2). 유예 중인 버전을 다시 설치하면 그 항목을 설치 대상으로 되돌린다. Codex를 빼면 Codex 유예 사본도 제거한다. 출처: `scripts/cairn-lifecycle-commands.mjs:194-216`, `test/lifecycle-transaction.test.mjs` "reinstalling a retained version adopts it and drops the retained entry", "a cross-version upgrade that deselects Codex removes its cache runtimes and keeps retaining the canonical runtime".

- G1: `codex-cli 0.164.0`은 `CODEX_HOME` 밖(`CAIRN_HOME/install/codex`)의 `source_type = "local"` marketplace를 받아들인다. 출처: `test/lifecycle-transaction.test.mjs:1406`("Codex A/B gate …"), `docs/plan/auto-upgrade-cairn-home.md` Evidence `cairn-home-layout`.

### Claude Code 플러그인 등록과 캐시 갱신

- 파일 commit 뒤 `claude plugin marketplace add <install/claude> --scope user`와 `claude plugin install cairn@cairn --scope user`로 등록한다. 이미 설치돼 있고 캐시 버전이 릴리스와 다르면 `claude plugin marketplace update cairn` → `claude plugin update cairn@cairn --scope user` 후 `plugin list`로 버전을 다시 확인한다. 같으면 update를 호출하지 않는다. 출처: `scripts/cairn-lifecycle-claude.mjs:127-175`, `test/lifecycle.test.mjs` "upgrade refreshes a stale Claude Code plugin cache to the installed version", "upgrade does not call claude plugin update when the cache already matches".
- 갱신 실패는 설치를 유지하고 `Claude Code plugin cache refresh failed: <reason>. To finish: …` 수동 명령과 exit 1이다. `claude` CLI가 없으면 수동 등록 명령만 안내하고 exit 0이다. `upgrade --auto`에서는 갱신 실패·등록 실패·`claude` CLI 없음이 exit 3(`AUTO_UPGRADE_EXIT.manual`)이다. 다른 `cairn` marketplace는 건드리지 않고 `--auto`에서도 exit 0이다. legacy 이전 뒤 `claude` CLI가 없어 재등록하지 못하면(옛 등록 제거 실패도 같다) 수동 명령이 `claude plugin marketplace remove cairn && claude plugin marketplace add … && claude plugin install …`이다. 옛 등록이 지워진 경로를 가리켜 `marketplace add`가 이름 충돌로 실패하기 때문이다. 출처: `scripts/cairn-lifecycle-commands.mjs` `reportClaudeRegistration`, `test/lifecycle.test.mjs` "a failed Claude cache refresh keeps the upgrade committed, exits 1, and prints the manual command", `test/auto-upgrade.test.mjs` "upgrade --auto exits with the manual code when Claude Code is selected but the claude CLI is missing", "upgrade --auto exits with the manual code for a failed Claude cache refresh and 0 for a foreign cairn marketplace", `test/lifecycle-transaction.test.mjs` "migration without the claude CLI prints manual commands that remove the 0.6.0 registration first".
- doctor는 `Claude plugin files`, `Claude plugin registered`, `Claude plugin enabled`, `Claude plugin cache version`을 검사한다. 출처: `scripts/cairn-lifecycle-commands.mjs:346-357`, `test/lifecycle.test.mjs` "doctor fails when the Claude Code plugin cache version differs".

### 자동 업그레이드

- 기본 켜짐. `CAIRN_AUTO_UPGRADE=0|false|off|no`(대소문자·공백 무시), `<CAIRN_HOME>/config.json`의 `"autoUpgrade": false`, 또는 읽을 수 없거나 형태가 틀린 `config.json`이면 끈다. 출처: `scripts/cairn-update-state.mjs:17,62-74`, `test/auto-upgrade.test.mjs` "auto-upgrade is off for CAIRN_AUTO_UPGRADE=0, for config autoUpgrade false, and for an unreadable config".
- SessionStart hook은 설치된 canonical runtime에서 실행될 때만(자기 `.cairn-runtime.json`이 `install/runtime/<version>`을 가리킬 때) 동작한다. 설치 버전과 같은 runtime이고 `origin: "package"`이고 확인 시기가 됐을 때만 분리 프로세스(`stdio: "ignore"`, `detached`, cwd `CAIRN_HOME`)로 `cairn-auto-upgrade.mjs run`을 띄운다. 확인 시기는 `max(lastCheckedAt, installedAt)`에서 24시간이 지났고 `nextAttemptAt` 전이 아닐 때다. 출처: `scripts/cairn-update-state.mjs:105-150`, `test/auto-upgrade.test.mjs` "SessionStart from an installed runtime spawns a detached runner only when a check is due", "SessionStart from a source checkout never reads or writes update state".
- runner는 `update/update.lock`을 기다리지 않고 잡는다(잡혀 있으면 종료, 죽은 pid의 lock은 회수). `npm view cairn-ai@latest version --json` → 정확한 `x.y.z`(32자 이하)만 인정 → 설치 버전보다 높을 때만 `update/stage/`에 `package.json`을 먼저 쓰고 `npm install --ignore-scripts --no-audit --no-fund --no-save cairn-ai@<v>` → 패키지 검증(`node_modules`에 `cairn-ai`만, 일반 파일·디렉터리만, `package.json`·`.codex-plugin/plugin.json` 이름·버전 일치) → `node <stage>/node_modules/cairn-ai/scripts/cairn-lifecycle.mjs upgrade --auto`. 성공 판정은 manifest `version`이 목표 버전인지로 한다. 출처: `scripts/cairn-auto-upgrade.mjs:90-168,208-253`, `test/auto-upgrade.test.mjs` "the runner upgrades an older installation and writes one updated notice", "the runner rejects an invalid registry answer", "the runner refuses a staged package that fails verification", "a second runner exits while update.lock is held, and a stale update.lock from a dead pid is reclaimed".
- major 포함 모든 새 버전을 적용하고 다운그레이드하지 않는다. prerelease 설치는 같은 core 릴리스로 올린다. 출처: `scripts/cairn-auto-upgrade.mjs:220-228`, `test/auto-upgrade.test.mjs` "the runner does nothing when the installed version is equal or higher and never downgrades", "the runner upgrades a prerelease install to the same core release".
- 결과와 backoff: 조회·설치 실패와 runner의 예상하지 못한 예외(stage 준비 같은 파일 시스템 오류)는 알림 없이 1시간부터 2배씩 최대 24시간(`check-failed`). 검증 실패와 manifest가 목표 버전으로 바뀌지 않은 lifecycle 실패는 `failed` 알림(버전마다 1회)과 24시간부터 2배씩 최대 7일. manifest가 목표 버전이면 lifecycle exit 0은 `updated`, 3은 `manual`, 그 밖은 commit 뒤 오류로 `failed`(알림 규칙 같음)이고, 다음 확인은 이미 목표 버전이라 다시 설치하지 않는다. stage 삭제 실패는 결과를 덮지 않고 `last-run.log`에만 남는다(다음 실행이 stage를 먼저 지우다 실패하면 예상하지 못한 예외로 기록된다). 출처: `scripts/cairn-auto-upgrade.mjs` `runLocked`·`upgradeTo`, `test/auto-upgrade.test.mjs` "registry and install failures back off silently", "a failed lifecycle upgrade writes one failed notice per version and backs off", "an upgrade whose Claude cache refresh fails writes a manual notice", "the runner writes a manual notice when the claude CLI is missing", "the runner counts a foreign cairn Claude Code marketplace as a completed upgrade", "an error after the upgrade commits writes one failed notice and is not retried", "a stage that cannot be removed still records the result with a backoff".
- runner가 일하는 동안 uninstall이 끝나 lifecycle 뒤 manifest 파일이 없거나(`upgrade --auto`는 그때 아무것도 설치하지 않는다), lock을 잡은 뒤 manifest가 없으면 runner는 state·notice를 쓰지 않고 update lock을 놓은 뒤 uninstall처럼 update 상태를 지운다(`{"ran":false,"reason":"not-installed"}`). 거부된 lifecycle의 lock 때문에 빈 `install/` 디렉터리는 남을 수 있다(다른 거부된 실행과 같다). 출처: `scripts/cairn-auto-upgrade.mjs` `runAutoUpgrade`, `test/auto-upgrade.test.mjs` "a runner whose installation was uninstalled meanwhile writes no state or notice and removes update state".
- 한계: runner는 hook 프로세스의 env를 그대로 lifecycle에 넘긴다. `CODEX_HOME`·`CLAUDE_HOME`·`ANTIGRAVITY_HOME`·`ANTIGRAVITY_CLI_HOME`·`CODEX_CONFIG_PATH`가 설치할 때와 다르면 manifest의 경로가 허용 목록과 맞지 않아 lifecycle이 거부하고 `failed` 알림이 된다. 이 env로 설치했다면 hook 환경에도 같은 값을 두거나 자동 업그레이드를 끈다.
- `origin: "checkout"`(설치 소스에 `.git`이 있음) 설치는 hook이 spawn하지 않고 runner도 건너뛴다. 소스 체크아웃 실행(locator 없음)은 update 상태를 읽지도 쓰지도 않는다. 출처: `scripts/cairn-lifecycle-commands.mjs:120`, `scripts/cairn-auto-upgrade.mjs:114-118`, `test/auto-upgrade.test.mjs` "the runner skips a checkout-origin installation", "install from a git checkout records origin checkout".
- `upgrade --auto`는 runner 전용이다: 기록된 호스트를 유지하고, `--hosts`·`--allow-downgrade`와 함께 쓸 수 없으며, lock 안에서 schema 2 manifest가 없으면 `auto-upgrade requires an existing installation`(exit 1)으로 아무것도 설치하지 않는다(uninstall 경합). 출처: `scripts/cairn-lifecycle.mjs:120,132`, `scripts/cairn-lifecycle-commands.mjs:51-55`, `test/auto-upgrade.test.mjs` "upgrade --auto without an existing schema 2 manifest is refused and installs nothing".
- 파일: `<CAIRN_HOME>/update/{state.json,notice.json,last-run.log(64 KiB 상한),update.lock,stage/}`. uninstall은 lifecycle lock 해제 뒤 `state.json`·`notice.json`·`last-run.log`와 (runner lock이 없으면) `stage/`를 지우고 빈 `update/`를 제거한다. `config.json`과 `projects/`는 남긴다. 출처: `scripts/cairn-update-state.mjs:20-35,184-199`, `scripts/cairn-lifecycle.mjs:96-99`, `test/auto-upgrade.test.mjs` "uninstall removes update state and keeps config.json and projects".
- 버전 간 계약(runner는 옛 버전, 설치되는 패키지는 새 버전이므로 바꾸면 옛 runner가 깨진다): `cairn-lifecycle.mjs upgrade --auto` 호출 형태, `CAIRN_HOME/install/lifecycle.json`의 `version`(과 schema 2·`plugin`·`origin` 형태), `upgrade --auto`의 exit code 의미(0 완료, 3 파일은 commit됐고 Claude Code 단계만 사용자에게 남음, 그 밖은 미확인). runner는 exit code와 lifecycle 뒤 manifest(버전, 파일 유무)로 결과를 나눈다. 출처: `scripts/cairn-auto-upgrade.mjs:14-18`, `scripts/cairn-update-state.mjs` `AUTO_UPGRADE_EXIT`·`readInstallManifest`.

### runtime 해석

- 패키지 `hooks/hooks.json`은 Codex의 `${PLUGIN_ROOT}`를 쓴다. Claude Code는 `${CLAUDE_PLUGIN_ROOT}`만 확장한다. 그래서 install이 얇은 Claude plugin을 따로 만들고, 그 hook은 canonical runtime의 `cairn-state.mjs`를 절대 경로로 호출한다. 출처: `scripts/cairn-lifecycle-claude.mjs:10-62`.
- 설치된 skill·command·workflow 미러는 `references/cairn-runtime.json` 등 runtime locator로 `pluginRoot`, `entrypoints`, `resources`를 찾는다. 대상 저장소에서 Cairn 파일을 찾지 않는다. 출처: `scripts/cairn-paths.mjs:124-144`, `test/installed-plugin.test.mjs` "installed mirrors resolve Cairn resources through runtime locators".
- runtime 필수 파일은 진입점 7개(`cairn.mjs`, `cairn-lifecycle.mjs`, `cairn-state.mjs`, `cairn-toolcheck.mjs`, `cairn-goal.mjs`, `cairn-cleanup.mjs`, `cairn-auto-upgrade.mjs`)에서 정적 import를 따라간 closure다. `cairn-auto-upgrade.mjs`는 hook이 경로로 spawn하므로 진입점이다. 출처: `scripts/cairn-paths.mjs:146-160`, `test/packed-install.test.mjs` "runtime locator includes extracted goal CLI dependency".
- 패키지에서 runtime으로 복사하는 문서는 `docs/model-guidance/`뿐이다. 저장소의 `docs/memory`, `docs/plan`은 배포되지 않는다. 출처: `scripts/cairn-lifecycle-staging.mjs:160-174`, `package.json` `files`.

### CLI help·exit 규약

| 표면 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| root, `init`, `memory`, `plan` | 성공, help, version | `memory`/`plan` check 오류 | 사용법 오류 (`Cairn error: …`) |
| `cleanup` | 성공, help, version | 실행 오류 (`Cairn cleanup error: …` 한 줄) | 사용법 오류 |
| `goal`, `task` | 성공, help, version, 인자 없음 | 모든 오류 (`Cairn goal error: …`) | 사용 안 함 |
| `toolcheck` | 성공, help, version | 도구 누락·설치 거부 | 사용법 오류 |
| `install`·`upgrade`·`doctor`·`uninstall` | 성공, 인자 없는 `cairn-lifecycle.mjs`(usage) | 모든 오류 (`Cairn lifecycle error: …`), Claude 캐시 갱신 실패. `upgrade --auto`만 Claude Code 수동 단계에 3을 쓴다 | — |
| `auto-upgrade` | 성공, help, 인자 없음, `run`의 `current`·`skipped`·비활성 | 실행 오류 (`Cairn auto-upgrade error: …`), `run` 결과 `failed`·`check-failed`·`manual` | 사용법 오류 |

- root usage는 8 locale 모두 `install|upgrade|doctor|uninstall|auto-upgrade|…`이다. lifecycle usage(en·ko)는 `cairn install|upgrade [--hosts all|codex,claude,antigravity] [--allow-downgrade] | doctor | uninstall | toolcheck`다. 출처: `scripts/cairn.mjs:139-188`, `scripts/cairn-lifecycle.mjs` `t("usage")`, `test/cli-contract-hardening.test.mjs` "lifecycle commands accept only --hosts and --allow-downgrade on install and upgrade and keep the documented --help exception".
- `cairn auto-upgrade status|on|off|run`은 JSON 보고 1개를 출력한다. `on`/`off`는 `config.json`의 다른 키를 보존해 원자적으로 쓰고, 읽을 수 없는 `config.json`은 덮어쓰지 않고 exit 1이다. `run`은 주기·backoff를 보지 않고 즉시 확인한다. 출처: `scripts/cairn-auto-upgrade.mjs:41-88`, `test/auto-upgrade.test.mjs` "cairn auto-upgrade status|on|off reports JSON, writes config.json atomically, and rejects bad usage".
- `init`은 `--root` 외 인자를 받으면 아무것도 쓰지 않고 exit 2다. `init --help`는 파일을 만들지 않는다. 출처: `scripts/cairn.mjs:56-72`, `test/cli-contract-hardening.test.mjs` "init --help and --version exit 0 and create no files", "init rejects unknown options with exit 2 and creates no files".
- `goal`/`task`는 `--` 앞의 `--help`를 상태를 읽기 전에 처리한다. `--` 뒤의 `--help`는 `goal verify`로 그대로 넘긴다. 출처: `scripts/cairn-goal-cli.mjs:18-35`.
- `cleanup --check --yes`는 사용법 오류다. 출처: `scripts/cairn-cleanup.mjs:156`.
- `init` 템플릿(`INDEX_TEMPLATES`)은 짧은 인덱스다. `## Planning Rules`는 없고, 규칙은 `cairn-plan` 스킬에 있다. `init`은 기존 파일을 덮어쓰지 않는다. 출처: `scripts/cairn-state-init.mjs`, `test/contract-parity.test.mjs` "templates/MEMORY.md and templates/PLAN.md equal the English init templates".
- 남겨 둔 예외: lifecycle 명령은 `--hosts`·`--allow-downgrade`(install·upgrade)와 `--auto`(upgrade) 외 인자를 받지 않는다. `cairn install --help`는 도움말 대신 `Cairn lifecycle error: Lifecycle command install does not accept arguments: --help`를 stderr에 쓰고 exit 1이며 파일을 만들지 않는다. 내부 hook 스크립트 `node scripts/cairn-state.mjs init --help`는 인자를 무시하고 초기화한다. 출처: `scripts/cairn-lifecycle.mjs:107-134`, `scripts/cairn-state.mjs:42-50`.

## Policy

- lifecycle·자동 업그레이드 검증은 임시 HOME과 `CAIRN_HOME`·위 env로 격리하고, npm은 `CAIRN_NPM_CLI`(fake npm), claude는 `CAIRN_CLAUDE_CLI` 대역을 쓴다. 실제 `~/.cairn`, `~/.codex/config.toml`과 설치본에는 쓰지 않는다.
- 새 스크립트는 진입점에서 정적 import로 연결한다. 동적 import는 runtime closure에서 빠진다. 경로로 spawn되는 스크립트는 `runtimeEntryRelativePaths`에 넣고, `package.json` `check`의 `node --check` 목록에도 넣는다.
- 새 journal id·phase는 journal 허용 목록과 `expectedManagedTarget` 양쪽에 넣는다. 빠지면 중단 복구가 `unsafe entry`로 실패한다.
- 위 버전 간 계약 3가지는 바꾸지 않는다. 바꿔야 하면 옛 runner가 새 패키지를 설치하는 경로를 먼저 설계한다.
- 설치본은 upgrade 뒤 새 세션부터 hook에 반영된다. 열린 세션은 유예된 이전 runtime으로 3일 동안 동작한다(legacy 이전은 유예가 없어 세션을 다시 시작한다).
